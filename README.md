# VR Monitor

Android-приложение для использования смартфона в качестве экрана VR-гарнитуры. При подключении USB-устройства автоматически гасит подсветку и блокирует тачскрин, сохраняя при этом видеосигнал для очков. При отключении — восстанавливает всё обратно.

Протестировано на **OnePlus 15 (Android 16, KernelSU Next)**.

---

## Что делает

- Определяет подключение USB-устройства (OTG) по фактическому составу шины, а не по одиночному броадкасту — композитная гарнитура (HID + аудио + хаб) не снимает блокировку, когда отваливается одна из её подфункций
- Ждёт настраиваемое время, чтобы успеть нажать нужные кнопки на экране
- Гасит подсветку через прямую запись в sysfs — дисплей продолжает передавать сигнал в очки
- Блокирует тачскрин через `/sys/class/input/inputX/inhibited`
- Устанавливает таймаут экрана в `∞`, чтобы экран не заснул во время просмотра
- При отключении USB возвращает яркость в авто-режим и ставит заданный таймаут

---

## Как выйти из блокировки

Четыре независимых пути, чтобы погашенный экран никогда не оказался ловушкой:

| Способ | Когда работает |
|---|---|
| Отключить USB | Всегда |
| Нажать кнопку питания 4 раза подряд | Пока приложение живо |
| Кнопка «Аварийный сброс» в шторке | Если выданы уведомления |
| Root-сторож | Если приложение убито системой |

**Root-сторож** — это скрипт, запущенный в root-шелле и переживающий смерть приложения. Он следит за `/proc/<pid>` приложения: как только процесс исчезает, сторож сам возвращает яркость и снимает блокировку тача. Без него убитое OOM-киллером приложение оставило бы телефон с чёрным экраном и мёртвым тачскрином.

Первая версия сторожа следила за файлом-пульсом, который приложение обновляло раз в 5 секунд. На устройстве это дало ложные срабатывания: стоило телефону уйти в Doze, как система переставала уважать `PARTIAL_WAKE_LOCK`, таймеры приложения замирали, пульс протухал — и сторож снимал блокировку с полностью живым приложением. Наличие `/proc/<pid>` от таймеров не зависит вовсе.

Состояние блокировки пишется на диск до первой записи в sysfs, поэтому перезапущенный сервис знает, что именно нужно откатывать.

## Требования

- Android 8.0+ (minSdk 26)
- **Root-доступ** — KernelSU или Magisk
- USB OTG

## Установка

1. Скачайте APK из [Releases](https://github.com/davnozdu/vr-usb-monitor/releases)
2. Установите на устройство
3. Откройте приложение
4. Выдайте root в KernelSU Manager → SuperUser → VR Monitor → **Разрешить всегда**
5. Разрешите уведомления, когда приложение попросит — в уведомлении живёт кнопка аварийного сброса
6. Вернитесь в приложение: строка Root должна показать **«Root: доступен»**

Права в KernelSU привязаны к UID, а UID меняется при переустановке. Начиная с версии 2.0 релизы подписаны постоянным ключом, поэтому обновления ставятся поверх и root выдавать заново не нужно. Обновление с версии 1.x требует удаления старой сборки.

## Настройки

| Параметр | По умолчанию | Описание |
|---|---|---|
| Перехватывать очки | Вкл | Выключите, когда очки нужны как обычный монитор: экран телефона останется рабочим. Выключение снимает блокировку сразу и держится до тех пор, пока не включите обратно — переживает и отключение очков, и перезагрузку |
| Выключать подсветку | Вкл | Гасит экран через sysfs, сигнал для очков остаётся |
| Блокировать тачскрин | Вкл | Запись `1` в `/sys/class/input/inputX/inhibited` |
| Задержка перед блокировкой | 15 с | Время на нажатие кнопок после подключения (0–120 с, шаг 5 с) |
| Таймаут экрана после отключения | 15 с | Какой таймаут установить когда гарнитура отключена (15/30/45/60 с) |

## Как работает подсветка

Android ограничивает минимальную яркость через своё API — даже при `screen_brightness = 0` на экране остаётся едва заметное свечение. Приложение обходит это:

1. Отключает авто-яркость: `settings put system screen_brightness_mode 0`
2. Ставит яркость через Android API: `settings put system screen_brightness 0`
3. Пишет напрямую в sysfs: `echo 0 > /sys/class/backlight/panel0-backlight/brightness`
4. Повторяет запись через 5 секунд — display manager успевает перебить первую

При отключении USB яркость возвращается в **авто-режим**. Абсолютное значение `screen_brightness` намеренно не восстанавливается: шкала зависит от устройства (на OnePlus 15 это 0..4095, а не 0..255), и авто-режим сам выставит корректную яркость.

## Как устроен root-доступ

Все команды идут через **один долгоживущий `su`-шелл** ([`RootShell.kt`](app/src/main/java/com/davnozdu/vrapp/RootShell.kt)), а не через отдельный процесс на каждую команду. Так быстрее, не дёргает менеджер прав на каждый вызов и не оставляет невычитанных потоков: stderr дренируется отдельным демон-потоком, а каждая команда ограничена таймаутом — по истечении шелл убивается и пересоздаётся.

## Сборка

```bash
git clone https://github.com/davnozdu/vr-usb-monitor.git
cd vr-usb-monitor
./gradlew assembleDebug
```

APK: `app/build/outputs/apk/debug/app-debug.apk`

CI собирает debug и подписанный release при каждом push. Релиз публикуется по тегу `v*`.

Подпись release берётся из окружения — `KEYSTORE_FILE`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`. Без них release собирается неподписанным, а не падает.

## Разрешения

- `FOREGROUND_SERVICE` + `FOREGROUND_SERVICE_SPECIAL_USE` — фоновый сервис мониторинга
- `POST_NOTIFICATIONS` — без него уведомление foreground-сервиса не публикуется, а вместе с ним пропадает кнопка аварийного сброса
- `RECEIVE_BOOT_COMPLETED` — автозапуск после перезагрузки

Root-команды выполняются через `su` (KernelSU / Magisk).
